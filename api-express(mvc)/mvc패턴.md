# MVC 패턴 코드 작성 프로세스

## 1. MVC 패턴이란?
MVC 패턴은 애플리케이션을 다음 3가지 역할로 나누어 관리하는 구조입니다.

- Model: 데이터 처리, 데이터베이스 연결, 비즈니스 로직 담당
- View: 사용자에게 보여주는 화면 또는 응답 결과 담당
- Controller: 클라이언트 요청을 받아서 처리 흐름을 연결하는 담당

## 2. Express MVC 프로젝트에서의 역할 분리
현재 프로젝트 기준으로 각 파일의 역할은 다음과 같습니다.

- index.js
  - 서버를 실행하고 라우트를 연결하는 진입점
- route/productRoute.js
  - URL 경로와 컨트롤러를 연결
- controller/productController.js
  - 요청을 받아서 서비스 계층으로 전달
- service/productService.js
  - 비즈니스 로직 처리
- repository/productRepository.js
  - 데이터베이스 접근 및 쿼리 처리
- config/database.js
  - 데이터베이스 연결 설정

## 3. MVC 코드 작성 순서

### 1) 라우트 작성
먼저 사용자 요청 경로를 정의합니다.

- 어떤 URL로 요청이 오는지 정함
- 해당 요청을 어떤 컨트롤러 함수로 연결할지 결정

예시:
- GET /products → 상품 목록 조회
- POST /products → 상품 등록

### 2) 컨트롤러 작성
라우트에서 연결된 함수가 실행되며, 요청을 받아 서비스로 전달합니다.

- 요청 데이터 확인
- 서비스 호출
- 응답 처리

### 3) 서비스 작성
컨트롤러에서 받은 요청을 처리하는 핵심 로직을 작성합니다.

- 비즈니스 규칙 적용
- 여러 Repository 호출
- 예외 처리

### 4) Repository 작성
데이터베이스와 직접 연결되는 계층입니다.

- SQL 또는 ORM 쿼리 실행
- 데이터 조회/삽입/수정/삭제 처리

### 5) DB 설정 연결
데이터베이스 연결 정보를 설정합니다.

- 서버가 실행될 때 DB 연결이 가능하도록 구성
- 환경 변수 또는 설정 파일 사용

### 6) 응답 처리
컨트롤러에서 클라이언트에게 적절한 응답을 반환합니다.

- 성공 시 status 200/201 반환
- 실패 시 status 400/404/500 반환

### 7) 테스트 및 수정
코드를 작성한 뒤에는 다음을 확인합니다.

- 요청이 정상적으로 동작하는지
- 예외 상황이 처리되는지
- 라우트와 컨트롤러 연결이 올바른지

## 4. MVC 흐름 예시: 상품 조회
다음은 상품 조회 요청이 흐르는 과정입니다.

1. 클라이언트가 GET /products 요청
2. route/productRoute.js가 요청을 controller로 연결
3. controller/productController.js가 서비스 호출
4. service/productService.js가 비즈니스 로직 처리
5. repository/productRepository.js가 DB에서 데이터 조회
6. 결과를 컨트롤러가 받아서 응답 반환

이 흐름은 아래와 같은 구조로 이해하면 쉽습니다.

Client → Route → Controller → Service → Repository → DB

## 5. 작성할 때의 원칙

- 한 파일은 하나의 책임만 가지도록 분리한다.
- 컨트롤러는 요청 처리에 집중한다.
- 서비스는 비즈니스 로직에 집중한다.
- Repository는 데이터 접근에 집중한다.
- 응답과 예외 처리는 명확하게 작성한다.

## 6. 실무에서의 추천 작성 방식
프로젝트를 만들 때는 아래 순서로 작성하는 것이 좋습니다.

1. 라우트 먼저 정의
2. 컨트롤러 함수 작성
3. 서비스 로직 작성
4. Repository 작성
5. DB 연결 확인
6. 에러 처리 추가
7. 테스트 실행

이 순서를 따르면 MVC 패턴에 맞는 구조를 자연스럽게 만들 수 있습니다.

## 7. 한 줄 요약
MVC 패턴은 “요청 처리 → 비즈니스 로직 → 데이터 처리” 순으로 책임을 분리하여 코드를 깔끔하게 관리하는 방법입니다.
